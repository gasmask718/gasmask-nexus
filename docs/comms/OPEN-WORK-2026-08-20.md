## 1. Federal DNC data gap — LEGAL, nothing mitigates it today

**What exists:** `dnc_list` + `opt_out_events`, populated only by inbound STOP
handled through `handle_sms_opt_out`, plus manual entries. `isSuppressed()` reads
those two by last-10.

**What does not exist:** any federal/state DNC registry data. Zero rows in the
system came from the FTC National DNC Registry, and no scrubbing job exists. Every
suppression decision we make is against numbers *we* have already annoyed.

This matters right now because `business_leads` holds 46,000 scraped Google Places
numbers and Aldrin + Ralph are about to add more. Scraped B2B numbers were never
opted in. Wireless numbers in that set (see LINE-TYPE-VERDICT-2026-08-19.md — 990
mobile-only stores identified from a 3,437-number lookup) are the exposure.

**Work:** obtain org access to the federal registry (SAN required, per-area-code
fees), land a `dnc_federal` table keyed on `phone_last10`, add it as a third
anti-join in `isSuppressed()` and in the `v_*_prospects` views, and re-scrub on a
schedule because the registry changes. Until then the honest statement is: we
suppress people who told *us* to stop, and nobody else.

**Do not** let a scraped-lead calling campaign start before this. It is the one
open item that can produce a per-call statutory penalty.

## 2. Calling windows — prerequisite is built, enforcement is not

`recording_consent_policy` + zip-derived state + IANA timezone on the lead were
built for the recording-consent gate. Memory records that jurisdiction is *one*
prerequisite serving **two** gates: consent and calling windows. Only the first is
wired.

Today there are four independent, ad-hoc quiet-hour implementations —
`bulk-sms-processor`, `bulk-ai-call-processor`, `admin-notify`, `field-portal-comms`
— and no shared helper. The dial path (`va-power-dialer`, `brandaro-call-twiml`,
the TwiML `<Dial>` gate) has none: it can place a call at 3am recipient-local.

**Work:** `_shared/callingWindow.ts` exporting `withinCallingWindow(tz, now)`
(8am–9pm recipient-local, the TCPA floor; state overrides where stricter), fail
**closed** on unknown timezone exactly as `recordAttrFor` does. Enforce at the same
chokepoint suppression is enforced — the TwiML endpoint before `<Dial>` and
`send-sms` — not in each caller. Then delete the four ad-hoc versions.

## 4. Group D — direct Twilio callers, judgment per function

77 files still reference `api.twilio.com` outside `_shared/`. That count is not the
work — most are legitimately not senders. The split:

- **Diagnostics / credential checks / API reads** — `check-twilio-health`,

  `voice-pipeline-audit`, `va-recordings-audit`, `t7c-a-dallas-sid-lookup`,
  `fetch-twilio-conversation`, `twilio-voice-diagnose`, `comms-health-monitor`,
  `system-health*`. These read the Twilio API and send nothing. **Leave them.**
  Routing them through a send helper would be worse.
- **Recording fetch/proxy** — `play-twilio-recording`, `brandaro-recording-proxy`,
  `brandaro-fetch-recordings`, `brandaro-sync-recordings`,
  `start-call-recording`, `gasmask-call-recording-status`. Media path, not send

  suppression + (once item 2 lands) calling-window gate applied at the dial, and

- **SMS senders not yet on `sendSms.ts`/`twilioSend.ts`** — `ambassador-notify`,

## 5. Nobody is alerted when comms break — **DONE 2026-08-20**

`comms-health-monitor` is wired to `sendOpsAlert()` (`index.ts`, 6h dedupe per
target). Detection and sink are connected; a red check now leaves the database.

The `function_deployment` false positive is **fixed 2026-08-20**. It assumed any
Supabase-hosted alternate route not on the accepted list was undeployed and never
probed it. It now measures: `probeDeployed()` is the single shared rule and treats
2xx / 400 / 401 / 403 / 405 / 422 / TwiML as "our code answered". 403 is the
*correct* answer for a signature-verifying webhook — the old rule would have turned
every endpoint hardened in item 3 into a false alarm. Verified on a live run: the
17 `dc-inbound-call` warns cleared to pass, and `dc-call-status`,
`va-dialer-status`, `twilio-gather-webhook`, `brandaro-call-twiml` are now probed
directly and report pass on HTTP 403.

## 6. Unified inbox — one page over one of six inbound stores

`/communication/unified-inbox` reads `communication_logs` only, hard `limit(200)`,
no pagination. Invisible to it: `dc_call_logs` (inbound voice), 
`brandaro_inbound_messages` (47 rows, 100% unresolved, untouched since 2026-06-07),
`voicemails`, email. No assignment model, no notification on arrival, no
time-to-first-response measurement anywhere.

`brandaro_pending_messages` holds **2,706 pending** outbound drafts in an approval
queue nobody has cleared.

**Work, in this order:** notification on inbound arrival (cheapest, highest value —
right now an inbound message reaches a database row and stops), then widen
`useUnifiedInbox` to union `dc_call_logs` + `brandaro_inbound_messages` +
`voicemails`, then pagination, then assignment. Do not start by building a new
inbox.

## 7. Content-bearing comms view (`v_comms_content_stream`)

Spec written: `docs/architecture/content-bearing-comms-view.md`. Not scheduled.

`FinishedCallsBoard` and `ConversationsTab` keep client-side hand-merges because
`v_comms_touch_stream` is a touch index whose contract permanently forbids
`recording_url`, `transcript` and message bodies. Migrating them onto it would lose
columns users read today. The fix is a second, content-bearing, authenticated-only
view — not a widening of the touch stream.

Three hard parts, all in the spec: RLS with no store boundary to lean on;
`recording_url` in a view is not permission to render it raw; and
`ConversationsTab`'s live Twilio pull backfills messages that were never mirrored
into any table, which a SQL view cannot reach (mirror them first — that's the real
fix).

Build item 6 before this. An inbox that shows all inbound is worth more than a
tidier query behind two boards that already work.

## 8. Smaller, still open

- **`store_id` resolution on `v_comms_touch_stream` is 216 / 3,886.** Deliberate —
  1,608 ambiguous rows resolve to NULL rather than a guess. The way to raise it is
  better contact data, not a looser match. Don't "fix" it by taking the first match.
- **`va_call_logs.recording_url`** — 103 rows hold a URL shape that no longer
  resolves. Commented on the column, not migrated. Anyone rendering it directly
  gets a player bug that isn't one.
- **7 raw media `src` tags remain in dead/unused surfaces** (MEDIA-SRC-SWEEP-2026-08-20.md).
  Safe only because nothing renders them. Fix on next touch of those files.
- **6 `getPublicUrl` call sites against private or non-existent buckets.**
  `getPublicUrl` never fails — it lies. These return 403s or dead links.
- **POD publisher caveat** — Printify/Etsy need a *server-side* signed URL; the
  browser-side `SignedImage` path does not cover them.
- **Sending is not role-gated at the function boundary.** A VA session token can
  invoke a send function for any brand; number selection is by argument, not by
  caller identity. Related to item 4 — do it in the same pass.
- **No test/dry-run mode on the outbound dial path.** A developer cannot place a
  test call without dialing a real number. There is a synthetic-probe path for SMS
  (`SMhealth…` / `+15005550006`); voice has no equivalent.
- **No automated tests under `supabase/functions/**` for any comms path.**
- **Edge-function senders write no actor.** `communication_logs.performed_by` is
  populated by the frontend service only, so the audit trail is partial exactly
  where automation acts.
